# 给新项目一个自己的仓库

## 做了什么

按用户选定的名字，把项目整理为独立公开仓库 RY-word2PDF-archiver 的源码版本。README 和后续构建名称使用新名字，原来的 WPS 转换项目继续作为来源记录保留。上传源码、测试、启动入口、说明和工作记录，排除测试资料、压缩包、本机构建输出和运行缓存。这次不打包、不发布 EXE。

## 为什么做

现在已经包含压缩包拖入和解压、单会话 WPS 转换、绿盾整目录申请、PDF 验收、RAR 交付及自动清理，范围明显超过最初的单一转换器。独立仓库更容易说明用途，也不会把旧项目的使用入口突然换成另一套工作流。

## 值得记住的事

当前已登录的 GitHub 账号是 jedliuai，公开仓库名保留用户指定的大小写。旧仓库不推送；本地默认远程地址改为新项目，旧地址作为来源远程保留，避免后续误推。

发布前复测发现 AppData 的虚拟目录可能在创建前解析到 C 盘，而新文件实际落在 D 盘。已在文件、工作目录真正创建后重新记录实际路径，保留清理边界校验，不靠放宽检查绕过问题。对应清理用例连续复测和全部 50 项回归测试都用于发布前验证。

界面验证脚本也改为自己创建样本，不再依赖这台电脑此前生成的测试目录，这样从新仓库获取源码后仍能复现验证。

## 一句话亮点

从一个 Word 转 PDF 小工具，长成一套能从压缩包一路走到可交付归档的本地文档助手。
