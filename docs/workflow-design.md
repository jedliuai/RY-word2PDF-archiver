# Word 到 PDF 归档闭环

本次需求：沿用本机 WPS 的转换能力，整合另一个项目的递归 Word 清单、全选和删除交互，调用已安装的绿盾常驻服务，再生成真正的 RAR。采用原生 Tkinter 桌面界面，不启动浏览器。

## 流程决策

逐步点击最便于监督，但日常操作太多；无条件全自动容易误删；默认采用自动处理并在清理前暂停，另提供用户主动开启的自动清理。

顺序调整为：扫描 → WPS 导出 → 全部 PDF 申请解密 → PDF 结构、页数检查 → RAR 创建、完整性和成员检查 → 用户确认后将选中 Word 移入回收站。这样在删除之前已有可用交付物。全自动模式也必须通过全部检查。任何失败阻断清理；没有永久删除入口。

归档仅包含目录内全部 PDF，保留原目录结构，不包含 Word、日志或其他附件。RAR 放在源目录旁边，命名为“原名称-PDF.rar”，重名仅加“(2)”等序号，不带时间和随机码。WPS 按原来的获授权流程访问 Word，每批只启动一个会话连续导出。按用户最新指示，绿盾直接对整个处理目录及整个核对副本目录申请解密，不逐文件申请；解密后比较源文件和副本，识别透明加密字节变化。解密是否成功由递归复核加密头、数量、可读性和程序实际解析共同确认。

完整任务完成后自动删除转换临时文件、核对副本、旧 PDF 备份和本次工作目录。压缩包输入还自动删除本次解压目录及解压清单，保留原包与最终 RAR；直接文件夹输入保留该目录中的 PDF 与原有附件。人工确认阶段和失败阶段继续保留检查所需文件。清理必须核对原始包和交付包哈希、目录归属及新增文件，禁止递归删除原始目录；清理占用单独提示，不把已验证交付判成转换失败。

## 压缩包与拖入输入

使用 TkDND 接收一个文件夹或 ZIP/RAR，正确解析 Tcl 文件列表中的中文、空格和花括号。拖入选择输入，显式点击开始执行；也提供选择文件夹/压缩包按钮。文件夹直接处理；ZIP 用 Python zipfile，RAR 用 rarfile 与本机 UnRAR 按成员流读取，解压到独立短名称目录，保留原包。全部解压并校验后才进入转换，记录原包哈希与提取清单。子进程提供停止和超时，未完成目录不作为成功输入。

已有同名 PDF 默认阻断，避免误用旧件；显式允许重新转换时，先备份旧 PDF 到本机任务记录目录再替换。同目录同名不同扩展名的源文档直接阻断，避免互相覆盖。来源、PDF 和归档哈希写入本地任务报告。清理前重新核对文件清单和哈希，发现增删改立即停止。

## 界面

一屏提供目录选择、已有 PDF 的重转选项、自动清理开关、五步状态、文件清单、运行日志，以及开始、停止、继续等待解密、全选、取消全选、确认清理、打开交付目录。默认关闭自动清理。转换在独立子进程运行，设置超时；GUI 不执行 COM 和长耗时任务。

## 实现与验证

- `pdf_workflow.py`：扫描、状态、检查、暂停续跑和清理前置条件。
- `local_services.py`：绿盾本地命名管道、WinRAR 调用和回收站。
- `wps_worker.py`：独立 WPS COM 会话和页数采集。
- `desktop_app.py`：Tkinter 界面和事件队列。
- 原入口保留，提供源码双击启动；按用户最新要求暂不打包 EXE，待试用稳定后再打包。
- 测试覆盖转换遗漏、同名冲突、旧 PDF、加密等待、损坏 PDF、页数不符、压缩失败、归档成员遗漏、清理前文件变更和部分清理失败。用独立生成的样本文档进行本机联调，不删除用户真实文档。

## 已知边界

页数和结构一致不保证视觉排版一致，默认要求用户抽查后清理。绿盾审批取决于组织权限。WPS 弹窗或卡住时停止任务，仅终止专用 Python 工作进程，不强杀用户的 WPS。程序停止不撤销已经提交的解密申请或已经移入回收站的文件。日志位于本机用户数据目录。
