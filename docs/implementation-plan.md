# 归档闭环实现计划

目标：在原 Python/Tkinter 技术栈内完成可操作的本地桌面工具，设计见 [workflow-design.md](workflow-design.md)。按照用户交由本任务评估流程的要求，由当前会话直接实现和验证。

- [x] 实现本地接口：绿盾命名管道按源码现有 JSON 协议调用；只读状态探测先行；RAR 使用文件清单、关闭配置影响、创建后测试及成员核对；回收站必须允许失败而不降级永久删除。
- [x] 实现工作流：严格扫描、同名检测、独立转换进程、临时输出发布、源文件一致性、解密等待续跑、PDF 解析和页数、不可变归档清单、清理前全部重新校验、JSON 报告。
- [x] 实现界面：后台线程和队列，默认暂停清理，主动勾选自动模式，选中项批量清理，清晰错误和下一步。
- [x] 增加有意义的安全回归测试；用本机常驻服务状态和生成样本验证真实 WPS、RAR、GUI；测试只操作本次生成的样本。
- [x] 更新 README、启动脚本；按用户习惯记录中文 worklog。用户明确要求暂不打包，已停止构建，待试用稳定后再做 EXE。

联调记录：真实 WPS 导出两页与一页 Word，三份 PDF 全部解密、校验、归档，RAR 完整性/成员/解压内容哈希通过，两个生成样本实际进入回收站。发现并修复透明加密导致的源文件哈希变化，以及 Codex AppData 从 C 盘虚拟路径重定向到 D 盘时原子重命名失败的问题。

追加完成：支持 ZIP/RAR 与文件夹原生拖入；压缩包先在独立目录校验解压，再进入现有流程。用户纠正后，WPS 改为整批单会话连续转换，绿盾改为处理目录和核对副本目录整体提交。用户实际测试 ZIP 的 9 份 Word 已转换，12 份 PDF 全部校验并生成无密码 RAR，保留原压缩包和全部 Word。仍不构建 EXE。

收尾规则更新：结果文件和解压目录不带时间与随机码，重名仅加序号；完整任务结束后自动删除本次工作目录、备份、解压目录及清单。原始输入与最终 RAR 保留，直接文件夹输入还保留 PDF。等待确认和失败时保留工作文件。已有测试输出已去掉编号后缀，核对原包和最终 RAR 后清理了两个旧解压目录。

重点复核：已有 PDF 不被默默信任；子目录/中文名称和重解析点；解密待批不重复申请；用户中途修改源文件/PDF/RAR 会阻断删除；停止和失败后状态不得放行后续操作。
